# Job Application Tracker

A full-stack MERN portfolio project for tracking job applications, statuses, interview progress, notes, and dashboard statistics. Each user has private data protected by JWT authentication and server-side ownership checks.

## Features

- User registration, login, logout, and protected routes
- JWT authentication with hashed passwords
- Add, view, edit, and delete job applications
- Search, filter by status/type, and sort applications
- Dashboard with real status counts and recent applications
- Responsive React UI with reusable components
- Express REST API with validation, error handling, and MongoDB ownership checks

## Tech Stack

- Frontend: React, Vite, React Router, Axios, Recharts, CSS
- Backend: Node.js, Express, MongoDB, Mongoose, JWT, bcryptjs

## How It Works

Users register or log in from the React client. The API returns a signed JWT, which the frontend stores locally and sends as a bearer token for protected requests. The backend validates the token and always scopes application queries to the authenticated user's ID.

## Installation

```bash
cd job-application-tracker/server
npm install

cd ../client
npm install
```

## Environment Variables

Create `server/.env` from `server/.env.example`:

```env
MONGODB_URI=
JWT_SECRET=
PORT=5000
CLIENT_URL=http://localhost:5173
```

Create `client/.env` from `client/.env.example`:

```env
VITE_API_URL=http://localhost:5000/api
```

Never commit real `.env` files.

## Run Backend

```bash
cd server
npm run dev
```

Backend URL: `http://localhost:5000`

## Run Frontend

```bash
cd client
npm run dev
```

Frontend URL: `http://localhost:5173`

## Deployment

Backend deployment is prepared with `render.yaml`. In Render, set `MONGODB_URI` and `CLIENT_URL` as secure environment variables. `JWT_SECRET` can be generated by Render from the blueprint.

Frontend deployment is prepared with `client/vercel.json` so React Router routes load correctly in production. In Vercel, set `VITE_API_URL` to the deployed Render API URL plus `/api`.

## API Overview

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/applications`
- `GET /api/applications/stats`
- `GET /api/applications/:id`
- `POST /api/applications`
- `PUT /api/applications/:id`
- `DELETE /api/applications/:id`

## Database Information

The app uses MongoDB through Mongoose. Collections are created automatically when users and applications are inserted. Application documents include a required `user` reference, and all protected application operations are scoped to that authenticated user.

## Authentication

Passwords are hashed with bcryptjs. JWTs expire after seven days. The frontend redirects unauthenticated users away from private pages and clears invalid sessions on unauthorized API responses.
